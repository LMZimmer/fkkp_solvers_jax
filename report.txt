Readability review: fisher_kpp_jax + tests (2026-08-24)
========================================================
Suggestions only — no code changed. Ordered by value/effort. Tags:
behavior-neutral / API-BREAKING / OUT-OF-SCOPE. Effort: S/M/L.

Review basis: the working tree is mid-refactor — base.py already imports
`from .time_loop import ...` (base.py:39-53) but fisher_kpp_jax/time_loop.py
was never created, so `import fisher_kpp_jax` fails and the test suite cannot
run. The scan-driver code that belongs in time_loop.py still exists inline in
base.py at HEAD (36dbf11, lines 44-294); line references below marked [HEAD]
point there. Everything else references the working tree.

Ripple surface note: scripts/validate_against_original.py (named in the task)
does not exist; the live consumer of the public API is
scripts/run_reference_solves.py (FKPPSolver, params keys, and Result fields
stopping_criterion / final_stopping_quantity, lines 206, 223-224).

 1. Finish (or revert) the half-done time_loop split — the package is broken.
    Current: base.py imports Consts, GuardSpec, QuantitySpec, StepSpec, State,
    SHRINKAGE_LIMIT, VANISHING_DENSITY_LIMIT, _RUNNING, _STOP_SHRINKAGE,
    _STOP_THRESHOLD, _STOP_VANISHING, _no_guard, _run_time_loop from a
    nonexistent .time_loop module; ModuleNotFoundError on import.
    Proposed: create fisher_kpp_jax/time_loop.py from the block at
    [HEAD] base.py:44-294 (guard limits, stop codes, type aliases,
    SCAN_TRACE_COUNT, _no_guard, _scan_driver, _run_time_loop), with the
    rename the new imports already assume: _STOP_VOLUME -> _STOP_THRESHOLD
    (and, inside _scan_driver, volume_hit/stop_volume -> threshold_hit/
    stop_threshold, [HEAD] base.py:163-198) — the threshold stop fires in
    "mass" mode too, so "volume" was the wrong word. Three ripples to close:
    (a) test_no_retrace_on_repeat_solve (test_solvers.py:307-327) reads
        base.SCAN_TRACE_COUNT; it must switch to
        `from fisher_kpp_jax import time_loop` + time_loop.SCAN_TRACE_COUNT.
        Do NOT fix this by re-exporting the counter from base: a from-import
        binds the value once (0 forever), before == after always, and the
        test passes vacuously. Module-attribute reads only.
    (b) solvers.py currently gets State/Consts/StepSpec/GuardSpec/
        SHRINKAGE_LIMIT/VANISHING_DENSITY_LIMIT via base's re-export chain
        (solvers.py:33-41). Import them from .time_loop directly and trim
        base's import list to what base itself uses — no re-export façade.
    (c) module docstrings referencing "base._scan_driver" already updated in
        base.py; give time_loop.py its own short docstring (the StepSpec
        dynamic/static contract lives there).
    Rationale: unblocks everything else; the split itself is right — base.py
    drops from ~1000 to ~480 lines and the scan machinery gets one home.
    Effort: M. behavior-neutral (once complete).

 2. Grid-stage names in _run_pipeline say the wrong grid.
    Current: `state_full` (base.py:294) is the LOW-RES uncropped state, not
    full resolution; `final_state_low` (base.py:315) is the CROPPED state;
    `final_low` (base.py:354) is the uncropped low-res state. Two of three
    names mislead, and the two "final" names differ by one word for
    different grids.
    Proposed: name by the three grids the pipeline actually has, e.g.
    full-res: `full_shape` (already), low-res uncropped: `*_grid`
    (`state_grid`, `final_grid`), cropped: `*_cropped` (`final_cropped`).
    `initial_snapshot` can stay.
    Rationale: the pipeline is the core read of the package; a reader
    currently has to reverse-engineer which grid each dict lives on.
    Effort: S. behavior-neutral.

 3. FK / FK_2c: extract the shared tissue-solver base.
    Current: FKPPSolver and TwoCompartmentWithNutrientFKPPSolver duplicate
    _validate_extra (solvers.py:302-303 vs 402-403), _prepare_fields
    (305-309 vs 405-409), _crop_mask (316-317 vs 411-412) and the
    _gm_low/_wm_low attribute declarations verbatim; the tissue-validity
    expression `(wm + gm) >= min_tissue_fraction` is written three times
    (solvers.py:328, 419-421, 434-436).
    Proposed: an intermediate class (e.g. TissueFKPPSolverBase) between
    BaseFKPPSolver and the two solvers holding the four members plus a
    `_tissue_mask(cropped: bool)` helper for the threshold expression.
    Rationale: ~30 duplicated lines and a thrice-written invariant that
    must stay identical for the two precisions to agree.
    Effort: M. behavior-neutral.

 4. FK_2c step: 8 positional dyn scalars in lockstep across two functions.
    Current: _two_compartment_step unpacks an 8-tuple positionally
    (solvers.py:146-155) that must match the build order in _step_spec
    (solvers.py:455-464); a swapped pair would run and produce silently
    wrong fields. Same pattern at smaller scale in _single_field_step (two
    elements).
    Proposed: make each spec's dyn a dict[str, jax.Array]
    (`dyn["rho"]`, `dyn["dt"]`, ...) — a dict is an equally valid jit
    pytree with a stable treedef, so the no-retrace property is unchanged.
    Update the StepSpec/QuantitySpec/GuardSpec contracts accordingly.
    Rationale: self-naming at the point of use kills the ordering hazard
    and most of the unpacking boilerplate.
    Effort: M. behavior-neutral.

 5. User-input validation via bare asserts.
    Current: _validate_tissue_arrays is five asserts, one message-less
    (solvers.py:87-91); the DTI solver validates its diffusion_tensors
    input only indirectly, via asserts on the derived axial field AFTER the
    tensor math (solvers.py:635-640). Asserts vanish under `python -O`.
    Proposed: raise ValueError with messages; validate
    params["diffusion_tensors"] (ndim == 5, trailing (3, 3)) in
    AnisotropicFKPPSolver._validate_extra so bad input fails at
    construction like every other schema error, and drop the derived-field
    asserts.
    Rationale: consistency with the strict _merge_params behavior and
    -O-proof errors at the earliest point.
    Effort: S. behavior-neutral (exception type AssertionError ->
    ValueError on untested paths; solve() funnels both into the same
    error Result).

 6. Rename operators.edge_roll -> edge_shift.
    Current: edge_roll (operators.py:36) does not roll — it shifts with
    edge replication; "roll" describes the heritage np.roll implementation
    it replaced. The tests' independent spec already uses the honest name
    (_edge_shift, test_operators.py:29).
    Proposed: rename function (+ call sites in operators.py, solvers.py,
    test_operators.py); docstring loses the "jnp.roll where..." framing.
    Rationale: the current name actively suggests the periodic-wrap
    semantics the port exists to avoid.
    Effort: S. behavior-neutral (operators is not in the package __all__).

 7. Seed-check hooks: two hooks whose only content is history.
    Current: _check_seed_early / _check_seed_late (base.py:471-477) exist
    to replicate WHERE each original checked, and their docstrings describe
    that history rather than behavior. The DTI late check needs nothing
    computed after _prepare_fields, so the split is not load-bearing.
    Proposed: one `_check_seed()` hook called at the early site
    (base.py:274); FK and DTI both override it; delete the late call site
    (base.py:303). Docstring: one line ("raise if the seed voxel is outside
    the simulated tissue; runs after grid geometry, before dt").
    Rationale: one hook fewer, and the remaining docstring describes the
    contract instead of the ancestor.
    Effort: S. behavior-neutral for all tested paths (in a doubly-broken
    input the DTI seed error would now win over a crop error — error-path
    ordering only, untested).

 8. _merge_params is a validation grab-bag, and its helper mutates.
    Current: _merge_params (base.py:83-133) does alias handling, schema
    merge, stopping validation, precision validation and n_steps
    validation in one 50-line function; _validate_stopping_params
    (base.py:136-155) silently fills in the density_threshold default —
    a "validate" name with a mutation inside.
    Proposed: keep _merge_params to alias + schema merge; move the
    precision/n_steps/stopping checks into one _validate_common(merged,
    solver_name); rename the mutating part honestly (e.g. fold the
    density_threshold defaulting into _validate_common with a comment, or
    call it _resolve_stopping_params).
    Rationale: each function's name matches what it does; the mutation
    stops hiding behind "validate".
    Effort: S. behavior-neutral.

11. Scan driver: two non-idiomatic JAX forms (lands in the new time_loop.py).
    Current: the snapshot write uses lax.dynamic_index_in_dim +
    dynamic_update_index_in_dim in a nested closure
    ([HEAD] base.py:179-188); the jit wrapping rebinds the name after the
    definition (`_scan_driver = jax.jit(_scan_driver, ...)`,
    [HEAD] base.py:234-246).
    Proposed: `buffer.at[slot].set(jnp.where(do_record, field,
    buffer[slot]))` for the write; `@partial(jax.jit, static_argnames=...)`
    as a decorator. Same lowering, standard forms.
    Rationale: readers grep for .at[] and decorators; the current forms
    read as workarounds.
    Effort: S. behavior-neutral.

15. Cosmetic heritage-call-style sweep (one pass, numerically identical).
    - jnp.multiply(u, 1 - u) -> u * (1 - u) (operators.py:110,
      solvers.py:182); jnp.power(x, 2) -> x**2 (operators.py:155).
    - np.max([a, b]) / np.min([dx, dy, dz]) on Python floats in the three
      _time_step_count methods (solvers.py:349-355, 473-487, 703-713) ->
      max/min builtins (pure selection, value-identical). CORRECTION during
      implementation: np.power(m, 2) must STAY — measured NOT bit-identical
      to CPython's ** (numpy pow vs libm pow, ~0.1% of inputs), and a 1-ULP
      change in nt can flip ceil(nt) into a different step count.
    - solve()'s `self.params.get("verbose", False)` (base.py:241) ->
      `self.params["verbose"]` — defaults guarantee the key exists.
    - Missing blank line before _validate_tissue_arrays (solvers.py:85).
    Rationale: heritage NumPy call style suggests array semantics where
    there are none.
    Effort: S. behavior-neutral (same ops; the np->builtin swaps are
    bit-identical IEEE double arithmetic).
